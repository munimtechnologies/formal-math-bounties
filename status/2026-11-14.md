|---|---|---|
| Open bounties | 269 | **290** |

| Lean proofs accepted | 55 | 55 |

| Bounty on each of the nine featured problems | $3,491 | $3,375 |

- **21 new bounties.** The validator README describes a "November 13 release" that "prepares 327
  reward targets and 654 bundles", "including nineteen additional Erdős problems, algebraic Hilbert
  13" and "the rank-one abelian Stark conjecture associated with Hilbert 12". 19 + 1 + 1 = 21, which
  matches the rise in open bounties from 269 to 290. The README says the reviewed formulations for
  Hilbert 6, 12, algebraic 13 and 16 are published with "scope and claim-status records".
- The release report (`docs/review-decisions/2026-11-13-erdos19-hilbert-release/` in the validator
  repo) names the 19 Erdős problems: 151, 159, 295, 311, 322, 345, 388, 389, 393, 422, 423, 430,
  461, 462, 467, 472, 478, 483 and 545. Erdős 173 was retired, not added, because it already has an
  accepted solution. The community database github.com/teorth/erdosproblems (data/problems.yaml,
  read 2026-11-14) lists all 19 as "open" and formalized. It flags only #467, with "ambiguous
  statement". So none of the new bounties is known to be settled in the literature. If you look at
  #467, read the site's rule on capped defect awards for faulty statements first.
- Under the site's rule, a newly opened problem starts at 2.5% of the pool and rises to 12.5% over 15
  days while it stays open. With a pool of about $42,000 that is roughly $1,050 on day one, rising to
  roughly $5,250. Payment is in the subnet's alpha token, so the dollar figures move with its rate.
- No new reward was paid since 2026-11-13. Both dollar totals fell, the paid total by about 7.7%
  (the 11 November payout for Erdős problem 12 part iii now shows as $4,299, down from $4,656). That
  is the exchange rate moving, not money being taken back.
- One section of the validator README still describes "275 active audited targets" and "550
  immutable bundles", which does not match the release's 327 and 654. It may simply not have been
  updated.

## Pinned versions changed

- The how-it-works page and the validator's `pins.lock.json` now pin formal-conjectures commit
  **33b3c405** (full hash 33b3c405cc7f6499595ce65c50e86be40354d372). Earlier notes in this guide
  gave 17acb876, and the README gave 4b69a7dc; both are now out of date.
- Lean is unchanged at `leanprover/lean4:v4.35.0-rc2`.
- A diagram in the validator README still shows "Formal Conjectures 8432eac9…". The lock file
  is the one to trust, because it is what the validator reads.
- If you prepare a proof, build it against the pinned commit. The site says an earlier submission is
  still checked against the version of the problem it was written for.

## Other conjectures.io tracks

The homepage lists four speed tracks, each paired with a Lean proof that the faster code behaves
exactly like the original: Tensor kernels (live, 7 boards) and three ended ones, TorchLean kernels,
Float kernels and DEFLATE. The site also says that a proof of a faulty statement "can earn a capped
defect award instead of the bounty".

## SAIR Foundation

- The SAIR GitHub organisation now has 9 repositories. The new one is `mathathon-judge`, for the
  Caltech x SAIR Mathathon ("Old Problems, New Proofs": 126 problems, 82 Lean statements prepared
  by AI, written reports reviewed by a panel of five AI models). Round 1 was an onsite event at
  Caltech on 13-15 November, so it is not open to remote entrants. Round 2 is a two-month mentored
  project.

  lean-kernel-challenge was last updated on 2026-09-17. Stage 1 closes "November 20, 2026, 23:59 AoE
  (UTC−12)".
